# KUSE 模型评测看板

首页展示模型与分类的耗时、积分均值。点击单元格查看完整 Prompt 与 10 组执行记录。

数据快照：2026-10-12。均值仅统计已完成且指标为有效数值的记录。缺失值不计作零。

该目录的静态文件可通过 GitHub Pages 发布；不需要 ChatGPT 登录。

显示规则：耗时、积分及均值四舍五入显示整数；均值先按原始精度计算，再取整。CSV 导出使用同样的整数规则。数据文件保留原始精度以便核对。

质量评分入口位于平均积分之后，使用独立的 `quality.json` 与 `quality.js`。目前录入 Auto、Claude Haiku 5.5 和 GPT-6.1 Sol，各 80 条记录。Auto 和 Haiku 各 60 条最终评分，GPT-6.1 Sol 有 59 条最终评分。GPT-6.1 Sol 的 md_gen_07 无交付，按用户要求评分留空、从均值排除。Auto 的搜索研究和知识召回 20 条未提供文件产物、评分为空；Haiku 对应 20 条待提供回答。其他模型暂无评分，缺失值不计作零。质量分类均分与模型均分只对已有最终评分求均值。

评分明细保留完整 Prompt、最终评分、规则分、内容 / Judge 分、两项权重、封顶分、封顶前加权分、匹配产物、评分状态、检查与视觉评分明细及扣分依据，可按模型和分类浏览、搜索及导出 CSV。模型均分进入全部 80 条任务，分类单元格进入对应 10 条。

更新质量数据：运行相邻 source 目录的 `extract_quality.py`，同步生成的 `dist/quality.json` 到本目录，并更新 app.js 的质量数据版本参数及 index.html 的资产版本参数后推送发布分支。耗时/积分更新不覆盖质量数据。

图片模型在通用数据下方以独立 BENCH20 区块展示：6 个模型 × 2 类（图片生成、参考图编辑）× 每类 10 条 Prompt，共 120 条记录。使用独立的 `images.json`、`images.js`；筛选、排序与耗时/积分切换独立，不混入通用 BENCH80 的统计。点击分类进入 10 组 Prompt，点击模型均值进入全部 20 组；分类跨模型明细为 60 条记录。支持完整 Prompt 复制、附件文件名与 CSV 导出。`#images` 可直接定位到首页图片模型区域。

更新图片数据：运行相邻 source 目录的 `extract_images.py`，核对源表均值后同步 `dist/images.json`，更新 app.js 数据版本与 index.html 资产版本，并推送现有发布分支。原工作簿保持只读。

图片质量评分：图片区的平均积分后新增独立质量评分入口（`#image-scores`）。图片评分读取主工作簿“填写记录”R:T，保留源表最终分、Rule/Judge 权重及分数、封顶前分数、封顶分、最终产物文件名和完整评分依据。点击质量均值进入对应10组或全部20组Prompt；可导出评分CSV。图片分数不混入通用模型质量数据，缺失分数留空，均值按原始精度计算后取整。运行 `extract_images.py` 同步图片评分及执行数据。

视频模型：图片区域下方新增独立参数矩阵（`#videos`），4个Seedance模型、2种输入模式、24个参数组合、240条有效记录。每种模式按设置分辨率×设置片长比较，每个组合10场景，不混合不同参数覆盖范围计算模型排名。耗时、积分独立切换，均值使用原始精度后取整。点击组合查看10个完整Prompt、附件文件名与执行记录并导出CSV。未提供组合、实际产物参数和质量评分保持为空。完整Prompt从源表证据关联原测试集并核对SHA256，源表数据通过视频分组汇总逐组核对。更新运行 `extract_videos.py`，同步 `dist/videos.json`，更新app.js数据版本与index.html资产版本后推送现有发布分支。

视频展示调整：文生视频、图生视频作为同一张矩阵的两组类别列并排展示，保留各自分辨率×片长及10场景明细。无需评测的无记录组合显示 `/`，有记录但指标缺失仍留空。取消输入模式切换，参数筛选同时作用于两类列。

视频区移除成本展示（总览、明细及CSV），仅展示耗时与积分。文生视频、图生视频类别标题加大加粗，使用更明显的蓝/绿色表头色块、底线与类别分界。
